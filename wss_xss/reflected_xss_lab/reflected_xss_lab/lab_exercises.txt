LAB EXERCISES: REFLECTED XSS

Exercise 1:
-----------
Open vulnerable.php and test normal input such as:
hello world
Observe the output.

Exercise 2:
-----------
Enter this payload:
<script>alert('XSS')</script>
Question:
Why does the alert box appear?

Exercise 3:
-----------
Use this payload:
<b>Cybersecurity Lab</b>
Question:
Why is HTML rendered by the vulnerable page?

Exercise 4:
-----------
Open secure.php and repeat the same payloads.
Question:
Why do they no longer execute?

Exercise 5:
-----------
Identify the vulnerable line in vulnerable.php.
Task:
Explain why direct output of user-controlled data is dangerous.

Exercise 6:
-----------
Compare these two lines:
echo $q;
echo htmlspecialchars($q, ENT_QUOTES, 'UTF-8');
Question:
What is the difference?

Exercise 7:
-----------
Modify vulnerable.php and add protection using htmlspecialchars().
Test again.

Exercise 8:
-----------
Explain the difference between:
- reflected XSS
- stored XSS
- DOM-based XSS

Exercise 9:
-----------
Create a short report with:
- attack input
- page behavior
- root cause
- mitigation

Exercise 10:
------------
Teacher discussion:
Ask students whether reflected XSS works only when a victim opens a crafted link.
Then discuss realistic attacker benefit such as:
- session theft
- phishing UI injection
- forced actions in browser context
- page defacement
